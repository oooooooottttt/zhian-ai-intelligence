## 一致性与纠正

monitor 的 `observations`/`revisions` 是原始证据；`kb_*` 保存清单、任务、派生实体、结果与会话。原始修订和知识失效在同一 SQLite 事务提交。原监测别名合并仅用作候选桶，当前实体依最新未撤回修订重核，历史别名不能作为当前事实。

任务签名覆盖当前修订及指纹、实体代次、映射、清单快照、来源权限/使用条件和算法版本；处理资格覆盖 owner、attempt、status 与未过期 lease。计算在事务外进行，取得写锁后再校验和发布。计算期间发生变更、旧进程返回、处理期限过期或事务失败，都不能留下部分“ready”结果。

来源撤回保存新修订，旧事实立即 dirty，停止用于当前问答；新结论重新计算。别名关系断裂进入 quarantined；完整、无重复的分区以 expected_generation 确认后重新派生。问答使用主机独立复制的请求前快照，模型输出只可选择获准事实卡；提交前核对当前元信息、实体与证据，引用来源字段由数据库重建。并发变化则返回 pending 并要求重问，不保存旧当前断言。

已保存回答是带知识代次的历史快照，不能永久标记为当前。资产过期只表示清单不够新，不表示资产已受害。新来源、复杂版本、许可拒绝和关联预算不足都保留未知或明示范围。

## 安全与边界

本地 HTTP 仅监听 127.0.0.1。读取校验 Host，写入同时要求同源 Origin、每进程随机 token、JSON 类型、明确长度和 1 MiB 请求上限。页面 nonce CSP、无外部资源、文本渲染、受控链接，不解释模型 Markdown。敏感凭据不接受进入清单或问句，不回显未知异常。

公开参考链接不是执行权限。仅登记的来源接口会被监测模块访问；关联和 POC 线索不被抓取。显式许可拒绝的修订不能成为事实、关系目标或当前引用。风险候选无观察支持时仅以授权资产能力和快照为依据，不能成为确认漏洞的问答断言。

## 验证方式

运行 `python3 -m unittest discover -v`。测试包含原监测分页/恢复/限流/事务/安全边界、数字版本范围反例、富化条件与分歧、网关传输假对象、真实 Harness 工具反馈、撤回和旧修订过滤，以及整合任务/库存/权限/问答/HTTP 请求边界。界面脚本测试用 Node 内置 VM（已有 Node 时）执行实际内联脚本，不安装任何依赖。

主聊天另以本机真实 HTTP 服务和浏览器验证情报详情、问题发送、逐条引用、清单导入和撤回后的历史标记。具体测试数量、浏览器检查和未验证项在最终交接中记录。离线假模型不证明真实模型可用；本轮未联网采集或执行目标操作。真实比赛覆盖率、准确率、性能、论文实验结论、生产标准/政策覆盖仍是后续验收内容。

## 当前容量

核心对账上限 5000 条观察，资产 256 项，单事件主证据 128、关联候选 128、事实 256、单结果 1 MiB。问答快照另有 1024 个事件、4096 份证据、4,000,000 个 UTF-8 字节的上限；页面拒绝超过 2,000,000 个 JavaScript 字符的响应文本。各层限制独立生效，5000 条观察不代表整个问答快照一定可用。

达到上限时不发布部分否定结论，保留错误或显示需要缩小范围的提示。首版对任一证据变更保守地使全部派生实体失效，便于保证纠正；更大数据量应将签名/失效改为依赖索引后再扩容，而不是放宽当前发布门槛。
