完成日期：2026-10-03。只修改了本聊天分配的三个文件：

- `aicti_core/ui.py`：提供完整自包含的 `PAGE: str`，不实现或启动 HTTP 服务。
- `tests/test_core_ui.py`：页面契约与实际内联脚本的离线行为测试。
- 本交接文档。

已阅读 AGENTS.md、冻结接口、共享类型、最终设计和原始赛题四页。原始 PDF 保留未修改。没有安装依赖、读取无关凭据、启动模型、联网采集、扫描资产、下载论文或 POC，也没有执行 POC。

## 已提供的操作

1. **情报概览**：监测 → 富化 → 资产影响 → 证据问答的流程提示；情报搜索、状态过滤和每页十条的客户端分页；事件详情包含范围、评分、条件、修复、关联材料、风险模式与资产判断。每个事件最多 256 项富化全部展示，其他未知谓词也有对应展示路径。
2. **证据与修订**：逐条引用按钮；来源、上游 ID、精确证据 ID、修订号、采集/发布/更新时间、摘要、署名与使用范围；历史修订与前一/最新修订导航。来源撤回和历史版本有明确标签。事件详情返回的 `evidence[].history` 可供详情弹窗展示，单独 evidence API 无须增加字段；访问原始修订时仍重新请求 evidence API。
3. **授权资产**：完整快照列表、清单时间和年龄、版本/暴露/认证的未知项；小表单、新增/移除、编辑现有清单、虚构示例；CSV/TSV 文本导入。清单时间必须明确填写，带时区时间转成 UTC，不将真实清单的缺失时间改成提交时刻。唯一例外是用户主动载入的虚构示例，其提示明确说明时间取当前演示时刻。
4. **影响与建议**：显示 `potentially_affected`、`under_investigation`、`not_affected_with_reason`、`resolved` 的中文标签、版本匹配状态、原因、缺失条件和精确来源。dirty/quarantined 事件不展示旧事实和旧判断。修复卡保留来源报告、尚未验证的状态。候选风险模式主区显示中文模式、资产名、声明能力和清单时间，核验字段在折叠区；不会把能力组合提示写成已确认漏洞。
5. **问答**：小问题输入、示例问题、会话选择和新会话、逐事实卡引用、回答方式、核验快照、证据来源与路径。存在 claims 时主区只显示逐卡文本和引用，合并全文折叠，避免重复。模型未启用、配置本地模型/检索模型、每次实际降级，以及 `mode: pending` 都分别说明。主聊天新增会话读取 API 后，选择未在本页缓存的已有会话会恢复历史问题、回答和精确引用；保留历史 epoch/stale，不用当前代次覆盖旧记录。新的 policy_generation 会立即清空旧会话缓存、撤销正在进行的旧读取并重新按当前权限读取活动会话。重读期间不显示旧正文与引用；权限变化后使用服务器隐藏后的内容，不复原被隐藏的来源或正文。
6. **运行状态**：来源成功/等待接续/退避状态与使用条件，近期任务、尝试次数和错误，手工检查来源、手工继续处理、刷新工作台。离线虚构演示有持续横幅与撤回按钮，采集按钮禁用。
7. **高级人工核对**：仅 quarantined 事件出现分区表单，以每份原始观察的下拉归属和理由形成分区，不要求填写 JSON。请求携带主聊天补充的 `expected_generation: event.generation`；任一事件证据在当前快照无法解析、分组缺失或非法时禁止提交。后端仍须核对包括权限外观察在内的完整覆盖及 generation。

## 接口与并发处理

使用约定的 `/api/system`、`/api/events/<id>`、`/api/evidence/<id>`、`/api/assets`、`/api/process`、`/api/ask`、`/api/collect`、`/api/demo/withdraw`、`/api/entities/confirm`，以及根聊天在整合中补充冻结的 `GET /api/sessions/<32hexid>`；UI 没有自行增加服务端 API。所有 POST 为 JSON 并携带 `X-Monitor-Token`。支持根聊天整合后返回的 `event.stale`、`event.knowledge_epoch`、证据 `current/current_revision_number`、32 位十六进制 `session_id` 及 `mode: pending`。

撤回、资产提交和人工确认成功后立即使页面旧判断失效。进行中的刷新会排队补刷，不把后续刷新请求丢弃；低于已知 knowledge epoch/资产快照 ID 的旧响应被拒绝。写入完成还会推进浏览器内的读取屏障，拒绝写入完成前已发出的旧 GET。写响应没有 epoch 时仅使用**写请求开始时**捕获的 baseline+1，不使用响应到达时的新快照加一，避免并发刷新已到 epoch 2 却误等 epoch 3。初始 epoch 不知道时使用读取屏障补刷，不捏造代次。单批刷新最多三次，持续收到旧数据时保留待重新核验状态并要求手工重试。新详情的 generation、epoch 或 `stale: true` 不能被较旧的 ready 快照覆盖。

旧回答保留自己的 epoch、as_of 和原修订引用。仅资料代次变化时标记“待重新核验”，不会仅凭 epoch 改变宣称原答案错误；精确引用被撤回或已有新修订时标记历史。问答请求在撤回后才返回，也不能恢复成当前结论。断连显示最后同步时间；页面保留上次数据，同时明确当前状态未重新核验。

可选状态刷新默认关闭，每 20 秒一次、每次勾选最多 30 次，隐藏页面期间暂停请求，离开页面取消。并发补刷单批仍最多三次。普通请求 20 秒，问答 45 秒；输入在失败时保留，不展示未经完成核验的部分回答。提交期间阻止重复请求与清单编辑。

## 安全与边界

- 仅两个 nonce 内联资源，`__NONCE__` 与 `__TOKEN__` 由根聊天服务器替换；没有外部字体、脚本、图片或 iframe。服务器继续负责 Host/Origin、CSP、请求体、身份与业务校验。
- 所有外部文字通过 `textContent` 显示；没有 innerHTML/outerHTML、HTML 模板注入、Markdown 执行或动态代码求值。模型文字、来源标题和恶意标签均作为文字。会话内容只留在当前页面内存，没有 localStorage/sessionStorage。
- 所有来源/许可/参考/修复链接经过同一 `publicURL`。拒绝危险协议、相对地址、反斜杠/控制字符、用户名密码及 token/api_key/password/signature 等敏感查询或片段键。URL 标准化之后阻断 IPv4 私网、回环、链路本地、共享/组播/保留字面地址；十进制、八进制、十六进制与短写回环都被覆盖。保守地拒绝全部 IPv6 字面地址，包含公网 IPv6。阻断 localhost、单标签主机及常见内部域后缀。新窗口链接为 `noopener noreferrer` 且无 referrer。
- 浏览器链接校验不能验证 DNS 实际解析或后续跳转；不将它宣传为 DNS 重绑定防护。后端对任何真正网络请求仍须使用既有网络安全策略。UI 不自行请求外部链接数据。
- 清单表单支持最多 256 项，避免编辑服务器已有 256 项清单时静默丢行；文本导入单次最多 100 项、64 KB。字段固定，拒绝任意 URL/脚本字段、凭据、重复 ID 和无效/未来时间。空版本归一为服务器接受的 `unknown`；暴露/认证未知发送 null。能力限定 `external_documents/rag/tools/network/write_access` 的布尔值，未知能力不发送；保留已有清单中这些项的已确认值。

## 验证

运行 `python3 -m unittest tests.test_core_ui -v`，35 项全部通过；使用 Python 3.14 的标准库 unittest 和现有 Node 内置 VM，没有安装依赖或启动服务。

三个静态测试检查完整 HTML、nonce、无外链资源/内联事件属性、不解释 HTML/Markdown、DOM ID、冻结 endpoint、POST token 和导航。三十二个行为测试直接执行 PAGE 中的实际脚本，覆盖：

- 恶意标题、摘要、元数据和模型文字的文本渲染；危险链接、非规范私网字面地址、敏感 URL 查询/片段键。
- CSV/TSV 引号、BOM、UTC 转换、未知项、大小/条数、非法字段、凭据、原型键、重复资产和无效时间。
- 提交失败保留输入、重复提交门禁、逐 claim 独立引用、dirty 事件不复活旧卡。
- 撤回期间的旧回答、变更后排队补刷、过低 epoch 拒绝与补刷上限、较新或 stale 事件详情、缺失证据分区拒绝、generation 绑定。
- 断连保留快照与同步提醒、离线采集禁用、可选轮询上限/隐藏暂停、历史证据的 current 标记和 revision 导航、事件 history 接入。
- 全部 256 富化卡、内部字段折叠、中文条件、pending 状态、逐条事实与全文折叠。
- 三个实际写入 handler 的响应晚于新快照到达时不多算代次；初始 epoch 未知时的写入屏障。
- 历史会话配对、精确引用与旧代次、权限隐藏内容、恢复时同步新快照、选择竞争、读取失败重试、有效 session 的 pending 回答，以及真实任务 `retry_wait/succeeded` 的中文显示。
- policy_generation 变化时先清空已缓存的撤权正文/引用，再恢复隐藏后的内容；权限变化前已发出的会话读取也不能把旧正文带回页面。

Node 仅用于测试实际 JavaScript，不是运行应用的依赖。若环境没有 Node，unittest 会明确跳过三十二项脚本行为测试，而不是将它们记作通过。

本聊天未启动服务或独立进行真实浏览器检查。根聊天已反馈主要真实浏览器通路可用，并据其产品反馈完成文案/字段折叠调整；最后这批调整的真实布局、键盘交互、HTTP/CSP、最终截图及全系统端到端验证仍由根聊天负责。本测试的最小 DOM 不证明浏览器布局或完整可访问性。PAGE 是 Python 模块常量，已有服务进程需要由根聊天重启后再刷新页面，才会使用最后的代码。

## 真实限制

刷新页面/服务重启后可选择已有会话，通过根聊天新增的历史 API 恢复服务器返回的最近消息。每会话显示最多最近 30 轮，读取失败可重试；没有可显示记录时明确说明。选择其他会话或新建会话后，较早返回的读取结果不能覆盖新选择。没有新增第二份持久化知识真相。

页面从 `/api/system` 读取快照并客户端分页；最多读取 5000 个事件/证据，单次 JSON 文本超过 2 MB 会报可见错误而不是悄悄部分显示。大型数据集需主聊天以后提供有界服务端分页，不声称已具备大规模生产能力。历史列表最多三十个修订，并可继续逐个读取前一修订。复杂版本、资产配置、许可和归因的正确性仍由业务模块提供，UI 不自行发明结论。没有宣称任何准确率、语义支持实测或响应时间达标。
